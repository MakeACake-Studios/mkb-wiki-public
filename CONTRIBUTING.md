# Редактирование wiki

## Метаданные статьи

Каждая статья начинается с YAML-блока:

```yaml
---
title: "Блок света"
order: "20"
banner:
  src: "../../assets/feature/light-banner.webp"
  alt: "Блок света"
  position: "center 40%"
---
```

- `title` — название в боковом меню;
- `order` — порядок статьи, если он важен;
- `banner` — необязательная обложка;
- `position` — точка фокуса баннера в формате CSS `object-position`.

## Поддерживаемый Markdown

Разрешены заголовки, абзацы, жирный и курсивный текст, зачёркивание, ссылки, списки, цитаты, таблицы, код и изображения. Сырой HTML и исполняемый код запрещены.

Внутренняя ссылка указывается от корня wiki:

```md
[Прочитать про блок света](/feature/light)
```

### Информационные блоки

```md
:::info{title="Важно"}

Текст информационного блока.

:::
```

Вместо `info` можно использовать `tip`.

### YouTube

```md
::youtube{id="dQw4w9WgXcQ"}
```

### Подчёркивание и спойлер

```md
:underline[подчёркнутый текст]
:spoiler[скрытый текст]
```

### Изображение фиксированной ширины

```md
::image{src="../assets/example.png" alt="Описание" width="400"}
```

### Группа изображений

Чтобы вывести несколько изображений одной адаптивной группой, используйте `gallery`:

```md
:::gallery{columns="3"}

![Первое изображение](../assets/example-1.png)
![Второе изображение](../assets/example-2.png)
![Третье изображение](../assets/example-3.png)

:::
```

Изображения складываются в адаптивный коллаж: первая картинка показывается крупнее, а
остальные заполняют меньшие ячейки вокруг неё. Параметр `columns` необязателен и задаёт
плотность больших групп; можно указать `2`, `3` или `4`. На узких экранах композиция
перестраивается в компактную мозаику. Внутри `gallery` должно быть не менее двух изображений
и не должно быть текста.

## Изображения

- Добавляйте файлы только в `assets/`.
- Используйте PNG, JPEG, WebP, GIF или SVG.
- Не добавляйте изображение, если оно уже существует.
- Старайтесь сжимать большие файлы перед загрузкой.
- Всегда указывайте понятное текстовое описание.

## Проверка pull request

GitHub автоматически проверяет метаданные, синтаксис Markdown, внутренние ссылки и существование всех локальных изображений. Pull request с ошибкой не может быть опубликован до исправления.
